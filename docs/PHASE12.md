# Phase 1.2 — Google Formsの2件の回帰修正

版0.9.8.3。既存のSafety Gatewayを維持し、field_policy.jsの判定とcontent.jsの設問・inspect参照だけを修正しました。rules、Gatewayの操作実装、プロフィール保存、数量、タブ処理は変更していません。

## 身分証記載の氏名

profile用途・通常のinput type=text・氏名分類で、身分証/本人確認書類等に「記載」された氏名を尋ねる文脈に限り、書類への言及による一律拒否を外します。書類のアップロード、添付、提出、選択、確認済み申告、認証、番号/コード等は引き続き拒否します。他の手動カテゴリ・型・用途キー・既存値・認証フォーム等の制約も残ります。

## Google Formsの設問解決

HTTPS docs.google.com/forms/d/でのみ、選択肢の内側コンテナから祖先をたどり、対応する設問境界内の一意のタイトルとヘッダーを解決します。role=heading、M7eMe/HoXoMd、対応する旧クラスを扱い、同じヘッダーの必須表示を確認します。フォーム/本文全体への探索、別設問のタイトル流用、複数タイトルがある曖昧な解決は拒否します。

policyの文脈・必須根拠とcontentのquestionContext/inspectでこの解決を共有します。「注意事項を全て確認しました。」「個人情報の取り扱いについて、同意します。」の必須「はい」が既存の専用Gatewayで一度だけONになります。任意・否定・手動対象・button/link/submit偽装、既存radio選択の維持は従来どおりです。

## 検証と制限

既存24件と回帰4件、合計28件成功。提供されたinspect結果の症状を再現する、内側の選択肢コンテナには「はい」だけがあり、外側にタイトルと必須マークがある代表DOMを使用しました。実フォームHTMLそのものは提供されておらず、今回の修正版を実Chrome・実サイトで確認した結果ではありません。

未知のDOM構造・曖昧な必須根拠・異なる氏名表現は手動になる場合があります。第三者サイトJSの許可イベントに対する通信/送信の副作用を完全に封じるものではありません。詳細な既存安全境界と制限はPHASE11.mdを参照してください。

本修正はDraft PR #2でレビューするためのものです。実運用フォルダと作成済みLATIAS_TEST_0.9.8.2は変更していません。正式反映前に既存の読み込み元を確認し、問題の2設問で再確認してください。
